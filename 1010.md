## 1. How to use this plan

Each task in §5 is a self-contained brief: goal, starting files, what done looks like, and size.
A session takes **one task increment**, follows ROADMAP_PARITY §6, and finishes with the §6
handoff template. To start one, paste:

```text
Implement task <ID> from 1010.md (it advances <card or roadmap section>).
Follow ROADMAP_PARITY.md §6 and the house rules in 1008.md §2 and 1010.md §2. Deliver one
reviewable increment, record it where the task says, and leave unproven gates open.
```

Sizes:
- **S:** one session.
- **M:** two or three increments.
- **L:** split before starting.

**Gated** tasks need a decision from the maintainer, hardware or a live service (§4). Work on the
highest-ranked ungated task first.

## 2. House rules

1008.md §2 still applies in full: shared checkout, no `cargo clean`, the three required checks,
targeted rustfmt, Python edit scripts, force-added evidence with hashes, `--no-ff` merges, lanes,
and honesty. These additions come from the 1008 sessions.

1. **The remote is `hookecho`, not `origin`.**
   ```bash
   git push hookecho feat/wsv3-redesign
   ```
2. **Regenerate the evidence manifest after each evidence commit:**
   ```bash
   python scripts/certification/manifest.py && python scripts/certification/readme.py
   ```
   Then commit `docs/certification/README.md` and `manifest.json`.
3. **Browser walkthroughs are real evidence** for workflows the desktop app cannot be driven
   through here:
   - Build with `HOOKECHO_WASM_BUDGET=8000000 HOOKECHO_WASM_RAW_BUDGET=26200000 bash
     scripts/web/build.sh`. `jq` is missing, so the lite page step fails after the main bundle
     is written; that is expected.
   - Serve with `target/release/hookecho.exe --serve 8080 --web-root web` through a temporary
     `.claude/launch.json` entry. That file is **tracked**: revert it after.
   - Drive the page with the built-in browser. The app draws to a canvas, so use its search box
     and screenshots. Analyst mode is under Settings → General → Diagnostics.
   - The browser preview can emulate a tablet viewport (`resize_window` preset `tablet`).
   - Label the result "browser build on WebGPU, one machine".
4. **Long runs must outlive the session.** Copy the binary aside and start it with
   `Start-Process`, stdout and stderr redirected.
5. **Measure in release** (`cargo test --release ... -- --ignored`), and say what else shared
   the machine. Do not overclaim timing: a cache hit is not a frame rate, and a counter is not a
   trace.
6. **Android code with no device here.** Kotlin and Gradle changes can be built and unit-tested.
   Behaviour on a device stays an open gate until it is shown on one (§4). Write which parts
   were verified how.
7. **Larger work goes to its own session.** Two are already proposed as session cards:
   - per-group GOES storage (V15 below);
   - HREF neighbourhood probabilities (V10).

   Check the linked sessions before starting either here.

## 3. The ranking

Value means value to the person using HookEcho. It is judged in this order:

1. **Safety:** could a warning go unseen?
2. **Reliability on the user's own device:** crashes, being killed by the OS, degraded modes.
3. **Reach:** how many users a change touches. The web build and Android reach the most.
4. **Frequency:** a live radar workflow used every storm day outranks an analyst tool used
   occasionally.

Effort and gating decide only the order between tasks of similar value.

## 5. Tasks, in value order

### P0 — warnings reach the user, and the app stays up on their device

**V1. The Android alert service must not crash after 6 hours.** *expansion.md §6.2. Size S.*
- Override `onTimeout(startId, fgsType)` in `AlertService.kt`: stop cleanly, and record the
  reason in the delivery-health line `platform::alert_health` already parses, so the user sees
  why the persistent notification went away.
- Write down the `dataSync` versus `specialUse` decision (§4).
- Test path: `adb shell am compat enable FGS_INTRODUCE_TIME_LIMITS io.hookecho.HookEcho`.

Done: built and unit-tested here. The device check is open until run on Android 15.

**V2. Android background alerts test real warning polygons.** *ROADMAP.md Later. Size M.*
- Today `Nws.kt` sends up to 40 `?point=` samples per pass: the centre and 6 rim points per
  saved place, and 8 vertices per drawn zone.
- Fetch the active alerts that carry geometry for the area, and test circle-polygon and
  polygon-polygon intersection in Kotlin. Keep `?point=` only for zone-only alerts (null
  geometry), which the server resolves.
- Tests:
  - a narrow polygon that passes between today's rim samples is caught;
  - zone-only alerts still arrive;
  - request volume stays within the existing cap.

**V3. Android 16 KB page alignment.** *expansion.md §6.1. Size S.*
- Move to NDK r28+ in `android/build.sh`, in `ci.yml`'s `android-check` and in `release.yml`,
  and in the F-Droid recipe in `android/README.md`. Alternatively add
  `-Wl,-z,max-page-size=16384 -Wl,-z,common-page-size=16384`.
- Add `zipalign -c -P 16 -v 4` to the release workflow beside the dangling-symbol check.

**V4. Android memory pressure.** *expansion.md §6.3. Size S–M.* Bridge `onTrimMemory` through JNI
to a cache-eviction hook covering the tile, field, volume and decoded-satellite caches. Then
measure a device-class memory budget (ROADMAP_NEW O1) once a device is available.

**V5. Web first load under budget.** *build.sh gates, expansion.md §4. Size M.*
1. Measure with `bloat.sh` (needs `twiggy`, §4).
2. Rank the contributors.
3. Move native-only code behind `src/native/` (expansion.md §4.3).
4. Add the `web/deps.lock` drift check (expansion.md §4.2).
5. Lazy-load or feature-gate what the browser does not need.
6. Report the result with and without `wasm-opt`.

Never raise a budget without the maintainer saying so.

## 7. Definition of done for a task increment

- The workflow works on desktop, or is shown in the browser build and labelled so. Android is
  built and tested here, with device proof stated as open until shown.
- The three checks pass, with logs. Android tasks also pass the Gradle build and unit tests.
- Tests cover missing and unknown data.
- There is a plain-language `CHANGELOG.md` "Unreleased" entry.
- The ledger or roadmap section records commands, results, hashed artifacts, and what remains
  open.
- Only the session's own files are committed and pushed to `hookecho/feat/wsv3-redesign`.
