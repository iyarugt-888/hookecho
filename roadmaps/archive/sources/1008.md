## 1. How to use this plan

Each task in §4 is a self-contained brief: goal, starting files, deliverable, proof and size. A
Claude Code session takes **one task increment**, follows ROADMAP_PARITY §6 ("Universal copyable
implementation prompt"), and finishes with the §6 handoff template. To start one, paste:

```text
Implement task <ID> from 1008.md (it advances ROADMAP_PARITY card <card>).
Follow ROADMAP_PARITY.md §6 and the house rules in 1008.md §2. Deliver one reviewable
increment, record it in the card's evidence ledger, and leave unproven gates open.
```

Sizes: **S** is one session, **M** is two or three increments, and **L** is a multi-increment
card that is split before starting.

## 2. House rules for every session

These come from this repository's working history. Skipping them has cost time before.

1. **Shared checkout.** Codex edits the same working tree. Stage only the files you changed,
   never `git add -A`, and check `git status` before committing.
2. **Never `cargo clean`.** `target/` holds review logs, the scientific corpus
   (`target/scientific-corpus/`) and caches. The backtest cache and exports live on
   `D:/hookecho-runs` through junctions in `target/`.
3. **Required checks before a commit:**
   - `cargo clippy --workspace --all-targets -- -D warnings`
   - `cargo test --workspace`
   - `cargo check -p hookecho --lib --target wasm32-unknown-unknown`. This catches native-only
     code such as rayon or `std::time::Instant` reaching the browser build. The existing
     warnings (1 in wxdata, 10 in hookecho) are the baseline.
   - Keep logs under `target/parity-review/<card>/`.
4. **Formatting.** `cargo fmt --all -- --check` already reports diffs in files nobody here
   edited. Run `rustfmt --edition 2021 <file>` on the files you changed, and only those.
   rustfmt follows `mod` declarations, so revert formatting-only changes in files you did not
   edit.
5. **Edit scripts.** Bash heredocs mangle backslashes. Write Python edit scripts to a file with
   the Write tool, then run them.
6. **Evidence that lasts.** `*.png` is ignored repo-wide. Reviewed captures under
   `docs/certification/` must be force-added (`git add -f`), as the m1.1 folders are. Record
   SHA-256 hashes in the card's README.
7. **Merging the cloud branch.** When the cloud session (`ccr-*` branch) pushes, merge it with
   `--no-ff` and never rebase pushed history. Expect `CHANGELOG.md` conflicts on adjacent
   "Unreleased" entries; keep both sides. Run the type check after every merge: the cloud
   branch is based on an older base and can use APIs this branch has since removed. One merge
   used `Theme::Dark`, which no longer exists; only `Theme::DearImGui` remains.
8. **Ownership.** The roadmap gives tornado-detection methodology, scoring, fusion, calibration
   and backtests to Claude, and WSV3 feature gaps to Codex (ROADMAP_PARITY §3). Sessions in
   §5's lanes must not touch another lane's files at the same time.
9. **Honesty.** Never invent clocks, units, quality or results. A compile or a software-GPU
   render is not device proof. A platform gate stays open until the workflow is shown on that
   platform.

## 4. Tasks

Waves are priority order. Within a wave, tasks in different lanes (§5) can run in parallel.

### Wave A — live-data trust (P0)

**A1. Warning latency and an optional push path.** *Card M1.3/M1.4. Size M.*
- Goal: measure how long a new NWS warning takes to reach the map, then cut it without adding
  a mandatory HookEcho service.
- Start: `crates/wxdata/src/alerts.rs` (polls `api.weather.gov/alerts/active`) and the fetch
  schedule (`crates/hookecho/src/app/fetch_schedule.rs`).
- Increment 1: instrument issue → receipt → drawn for alerts (reuse M1.2's stage timings) and
  publish p50/p95 against the NWS `sent` time on a live day.
- Increment 2: an optional user-configured NWWS-OI path (the user's own free NWWS account)
  through the existing relay pattern (`strikes-relay`, `radar-ingest`). Dedupe it against the
  API by VTEC, and label the source in the alert card. With nothing configured the app must
  behave exactly as before.
- Proof: a latency report, VTEC dedupe tests, and a live session where both paths ran.

**A2. Failover under load.** *Card M1.3. Size L.*
- Follow M1.3's "Next agent handoff": complete app delivery under direct and relay faults,
  failure-domain identity, cross-provider cut continuation, and a sustained live session report
  kept separate from simulator results.
- Start: `crates/hookecho/src/volume.rs`, `crates/wxdata/src/continuation.rs`,
  `docs/certification/m1.3/`.

**A3. Latency through to the screen.** *Card M1.2. Size M.*
- Correlate decode, acceptance and GPU completion with frame identity in one trace. Profile 3D
  upload and build.
- Measure on the RTX 2060 desktop and on one Android device.
- Show "receipt → on screen" with its measured stage named in the UI. Never present queue
  writes as visible latency.

**A4. Finish M1.4 lineage.** *Card M1.4. Size M. Lane: detection.*
1. Earlier volumes' passes behind a track's two-pass count. `llsd_analyst::PassConfirmation`
   counts across volumes; record each counted pass's volume and time per track.
2. The same lineage record for warnings (VTEC times) and observations (station clocks).
3. Archive receipts persisted with cached volumes. Unknown receipts stay unknown.
- Start: `crates/wxdata/src/detection_lineage.rs` and `crates/hookecho/src/app/detectors.rs`.

**A5. Canonical cut continuation.** *Card M1.1. Size M.* Provider loss, polling, and
deterministic restoration of the preferred tier, per the card's open items.

### Wave G — tornado detection (Claude-owned)

**G1. Pair debris reflectivity with its own CC cut, then backtest.** Proposed 2026-10-08 as a
separate session and not yet started. At split-cut tilts `newest_moment_sweep` gives the
debris detector reflectivity from the Doppler cut and CC from the surveillance cut, about 17
seconds apart (`docs/certification/m1.4/README.md`, "Debris inputs"). Adopt the change only if
the backtest in `detectionplan.md` does not get worse.

**G2. QLCS and shallow vortices.** *Size L.*
- The LLSD column stage misses small, shallow vortices that the original couplets partly see,
  at far more false alarms (ROADMAP_PARITY §2, "Tornado detection").
- Start from the misses already analysed in `detectionplan.md` ("What the radar showed at the
  missed tornadoes"). 72% had credible cyclonic rotation that was simply weak, at the strength
  where weak tornadoes and ordinary storm rotation overlap.
- The looser elongation gate was tried and rejected: it added only false markers on ordinary
  days. Do not repeat it.
- The open question is separating weak tornadic rotation from ordinary rotation with evidence
  beyond strength: near-storm environment, storm mode (QLCS against discrete) and persistence
  across passes.
- Proof: ordinary-day false markers per radar-hour do not rise beyond the documented
  tolerance, measured on the held-out years.

**G3. Calibrated likelihoods.** *Size M.* Scores are evidence, not probabilities. Fit a
reliability mapping (isotonic or Platt) on the training years, show reliability diagrams on the
held-out years, and only then word any tier as a likelihood. Keep detection language clear that
markers are not NWS products.

## 6. Definition of done for a task increment

- The user workflow works on desktop. Android is shown, or explicitly left open with the
  reason.
- The required checks in §2.3 pass, with logs saved.
- Tests cover the new behaviour, including missing and unknown data.
- `CHANGELOG.md` "Unreleased" has a plain-language entry.
- The card's evidence ledger records what was delivered, the commands and their results,
  artifacts with hashes, and what remains open.
- Only the session's own files are committed. The branch is merged, not rebased, and pushed.
