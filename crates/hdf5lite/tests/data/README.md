# Test fixtures

Real files, not synthesized ones — a reader that only ever sees output from its own imagination
learns nothing.

## `g19_day.nc`, `g19_night.nc`

GOES-19 GLM Level 2 lightning granules (netCDF-4), from two different hours so the day/night
difference in flash counts is covered. Public NOAA data from the `noaa-goes19` S3 bucket.

## `bewid.h5`

An ODIM_H5 polar volume from Wideumont, Belgium (RMI), 2013-04-29 04:30 UTC: five sweeps of
360 × 960 uint8 DBZH. Taken unmodified from
[wradlib-data](https://github.com/wradlib/wradlib-data) (`hdf5/71_20181220_060628.pvol.h5`'s
sibling sample `bewid.h5`), which publishes it as open sample data for the wradlib project.

It is committed whole at 341 KB. Trimming it would mean rewriting it through h5py, and a rewritten
file is no longer evidence of what the Belgian radar's own writer emits — which is the entire point
of having it. It exercises the structures netCDF-4 never produces: superblock v0, version-1 object
headers, symbol-table groups with a local heap of names, variable-length string attributes in the
global heap, and two-dimensional chunking.

## Goldens

Every `*.golden.json` is generated by `../gen_golden.py` using h5py, so the tests compare against
the reference HDF5 implementation rather than against ourselves. Regenerate after adding a fixture.

## `regression/abi_cmip_m6c13.nc`

A GOES-19 ABI-L2-CMIP mesoscale Band 13 (clean IR) granule, from the same public `noaa-goes19`
bucket as the GLM fixtures above — deliberately *not* alongside them, so `golden.rs`'s
`granules()` (which requires a `.golden.json` for every `.nc` it finds) doesn't pick it up; there
is no h5py in this environment to generate one. `abi_regression.rs` checks it against physical
plausibility instead of a reference implementation. Its `x`/`y` coordinate variables carry a
`DIMENSION_LIST` attribute (an array of HDF5 object references, a datatype this reader doesn't
interpret) whose dataspace this parser used to misread as a handful of enormous dimensions,
panicking on `usize` multiplication overflow computing the attribute's element count — every ABI
CMIP file has this attribute on its coordinate variables, so this is regression coverage for
`hdf5lite` opening ABI files at all, not just this one panic.
